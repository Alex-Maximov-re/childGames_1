# Лучик

Сборник игр для детей 3–12 лет. Внутри девять коротких игр, три возраста, звёзды на устройстве. Рекламы, аккаунта и отправки ответов на сервер нет.

Одни и те же игры собраны в три отдельных приложения. Звёзды у каждого свои.

| Приложение | Папка | Адрес для проверки | Куда публиковать |
| --- | --- | --- | --- |
| Веб | `apps/web` | https://alex-maximov-re.github.io/childGames_1/ | GitHub Pages |

Сайт собирает GitHub Actions из `apps/web` и публикует готовую игру. Если выложить корень репозитория, Pages показывает этот README, а не приложение.
| Android | `apps/android` | http://localhost:5174 | Google Play |
| iOS | `apps/ios` | http://localhost:5175 | App Store |

Игры можно собирать и проверять на Windows. Готовый файл для App Store собирается на Mac: Apple принимает приложение через Xcode, а Xcode есть только на macOS. Android-проект создаётся на Windows, а выпуск в Google Play удобнее из Android Studio.

## Игры

- 3–5 лет: Цвета, Фигуры, Кто говорит
- 6–8 лет: Пары, Сосчитай, Что лишнее
- 9–12 лет: Примеры, Продолжи ряд, Картинка

За лучшую попытку на карточке игры остаётся до трёх звёзд. Раздел «Родителям» закрыт примером: там звук, сброс звёзд и короткое объяснение, куда деваются данные.

## Запуск

```powershell
npm install
npm run dev:web
npm run dev:android
npm run dev:ios
```

`npm run dev` открывает веб-приложение на порту 5173. Android-оболочка слушает 5174, iOS-оболочка — 5175. Их можно запустить вместе: прогресс пишется в разные ключи браузера и на телефоне не смешивается.

Сборка всех трёх каталогов:

```powershell
npm run build
```

Веб-каталог лежит в `apps/web/dist`. Его можно выложить на сайт как есть: адреса внутри сборки начинаются от корня домена. Android-каталог — `apps/android/dist`, iOS — `apps/ios/dist`.

## Android

Идентификатор приложения: `com.luchik.android`. Замените его в `apps/android/capacitor.config.ts` на свой до создания записи в Google Play.

Нужны Android Studio и Android SDK. На этом компьютере:

```powershell
npm run android:sync
npm run android:open
```

`android:sync` заново собирает веб-часть и копирует её в проект `apps/android/android`. В Android Studio: Build → Generate Signed Bundle / APK и выберите Android App Bundle для Google Play. Перед выпуском уберите из конфигурации временный `server.url`, если добавляли его для отладки на эмуляторе.

Чтобы гонять игры с живым сервером внутри эмулятора, на время разработки можно дописать в `apps/android/capacitor.config.ts`:

```ts
server: { url: 'http://10.0.2.2:5174', cleartext: true, androidScheme: 'https' }
```

`10.0.2.2` — это ваш компьютер с точки зрения эмулятора. Для настоящей установки эту строку нужно убрать и снова выполнить `npm run android:sync`.

Кнопка «Назад» на Android возвращает из игры к списку, а с главного экрана закрывает приложение. Рекламы и отправки ответов нет, как и в остальных сборках.

## Публикация в App Store

Нужны:

- аккаунт [Apple Developer Program](https://developer.apple.com/programs/) (99 USD в год)
- Mac с актуальной macOS и Xcode
- уникальный идентификатор приложения. Сейчас в `apps/ios/capacitor.config.json` стоит `com.luchik.games`. Замените его на свой, например `com.вашеимя.luchik`, до создания записи в App Store Connect. Потом менять его больно

На Mac, в папке проекта:

```bash
npm install
npm install @capacitor/ios
npm run ios:sync
cd apps/ios
npx cap add ios
npx cap sync ios
npx cap open ios
```

В Xcode:

1. Укажите свою команду подписи (Signing & Capabilities).
2. Поставьте iPhone и iPad, портрет и ландшафт.
3. Минимальная система — iOS 15.
4. В `apps/ios/ios/App/App/Info.plist` добавьте ключ `ITSAppUsesNonExemptEncryption` со значением `NO`, если не добавляли свои алгоритмы шифрования. Так проходится вопрос про экспорт при загрузке.
5. Product → Archive, затем загрузка в App Store Connect.
6. Сначала раздайте сборку через TestFlight и пройдите игры на настоящем iPhone и iPad.

Если Mac только на финальном шаге, архив можно собрать на арендованном Mac или в облачной сборке (Codemagic, GitHub Actions с macOS). Сертификаты и профиль подписи всё равно выпускаются в аккаунте Apple.

### Детская категория

Приложение уже ведёт себя так, как просит детский раздел App Store:

- нет рекламы, аналитики и сторонних SDK
- нет ссылок наружу и нет просьбы оценить приложение
- нет аккаунта и нет сбора личных данных
- родительский раздел закрыт примером
- игры работают без интернета после установки: страницы лежат внутри приложения

В Kids Category возрастные полосы Apple — до 5, 6–8 и 9–11 лет. Если отметить все три, приложение должно подходить самому младшему возрасту: здесь нет страшного сюжета, чатов и покупок. Категория витрины: Education, дополнительная — Games. Возрастной рейтинг: 4+.

В анкете конфиденциальности отметьте, что данные не собираются. Политику конфиденциальности нужно выложить по публичному https-адресу: текст лежит в `public/privacy.html`. Перед публикацией впишите туда свою почту. Тот же адрес можно указать как страницу поддержки, если на ней есть способ с вами связаться.

Цену можно поставить на само приложение в App Store Connect. Покупок внутри игры в этой версии нет.

Иконка для магазина — квадрат 1024×1024 без скруглений и без прозрачности. Рисунок-основа — `public/favicon.svg`. Скриншоты снимайте на симуляторе тех размеров, которые App Store Connect пометит как обязательные, и покажите сами игры, не только меню.

Язык интерфейса русский. В App Store Connect основным языком можно поставить русский.

### Новая игра

Добавьте идентификатор в `GameId` (`src/types.ts`), карточку в `src/catalog.ts` и компонент в `src/games`, затем зарегистрируйте его в `src/games/index.ts`.
